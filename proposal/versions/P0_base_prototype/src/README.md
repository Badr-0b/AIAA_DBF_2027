Each section file opens with its rubric checklist. Inside it you'll find:
- `\dbfnote{}`: what each paragraph must say;
- `\dbffill{N}`: an N-word placeholder that holds the page budget;
- `\dbftbd{}`: values still to compute.

## How to write a section
1. Replace a `\dbffill{N}` with real prose of about N words. If you go over, take the words from somewhere else in the same section. The 6-page total is fixed.
2. Use the macros from `data/numbers.tex` (`\nSpan`, `\sTotal`, and so on). Never type a key number directly, so the summary, tables and text can't disagree.
3. Replace placeholders with real figures generated by `design-system/matplotlib/dbfplot.py` at the same size.
4. Captions state the takeaway. Every table and figure is referenced and explained in the text.
5. Cite sources in AIAA format as footnotes (the rules require footnotes in the proposal).
6. Delete a `\dbfnote{}` once its paragraph is written. The final build hides notes anyway.

## Lessons from the 2025-26 judges
- Give concrete mission math: numbers for every mission, a chosen plan, and a predicted score.
- Show how the optimum moves with the key parameters (sensitivity), then commit to one plan.
- State that the aircraft is pilot-in-the-loop with no autopilot. Hatch latches must be mechanical, not magnetic.
- Itemize the budget (test articles, crating, spares, consumables), name a confirmed funding source, and include contingency.
- Use all 6 pages, explain every table, don't restate the rules, and proofread twice.
